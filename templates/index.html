How to Setup
Get your Hermes Agent running in minutes
1 Get a Free LLM API Key
  1. Go to openrouter.ai and create a free account.
  2. Once logged in, go to openrouter.ai/workspaces/default/keys and click Create Key. Copy the generated API key — it starts with sk-or-...
  3. OpenRouter offers many models, including free ones. To get started, you can pick a free model such as: nvidia/llama-3.3-nemotron-super-49b-v1:free Browse all available models at openrouter.ai/models — filter by "Free" to see no-cost options.
  4. Head over to the Setup page (left sidebar), select OpenRouter as provider, paste your API key, and enter the model name. Want a different provider (Anthropic, DeepSeek, Groq, Cerebras, Mistral, etc.)? Open the Hermes Dashboard from the sidebar — the Keys tab lists every provider Hermes supports out of the box, plus skills, toolsets, and analytics you can configure from there.
2 Connect a Messaging Platform

Hermes Agent can work through messaging platforms. Connecting one is optional — the easiest to set up is Telegram.

  1. Open Telegram and search for @BotFather.
  2. Send /newbot and follow the prompts — give your bot a name and username.
  3. BotFather will reply with a Bot Token — it looks like 1234567890:ABCdefGhIjKlMnOpQrStUvWxYz. Copy this token.
  4. Go to the Setup page, enable Telegram under Messaging Channels, and paste the Bot Token.
  5. For Allowed User IDs, if you're just starting out, enter * to allow all users. You can restrict access later by specifying individual Telegram user IDs.
  6. Click Save & Start on the bottom right — your Hermes Agent is now live!
Facing an issue or something not working as expected? Create a GitHub issue and we'll help you out.
What's New
Changes and updates to this template
main always ships the latest release — that is what you get by default. To stay on, or roll back to, a particular Hermes version, point your Railway service at that release's branch and redeploy.
Release branches are named release/<hermes-version>/<n>. /1 is where that Hermes version first landed; /2, /3 and so on are template-only fixes and improvements on top of it — the Hermes version never changes within a series. Pick the highest number for the Hermes version you want; each branch stays put once published.
August 8, 2026
Git branch release/v2026.8.3/1 Hermes compatible version v2026.8.3
Hermes update
  • Updated Hermes Agent to v2026.8.3 (from v2026.7.20, covering two upstream releases) — adds video generation tools, the Vercel AI Gateway and Vertex providers, outbound webhooks, and gateway health monitoring.
  • Fewer out-of-memory restarts — Hermes now returns unused memory to the system as it runs, which directly targets the crashes that hit long-running bots.
  • An interrupted message is retried automatically. If your bot is killed mid-answer (an out-of-memory crash, or a redeploy), Hermes now re-runs that message when it comes back instead of losing it. Left enabled — but if the message asked for something with real-world side effects, it will be carried out a second time.
Changes to support upstream updates
  • Restart no longer parks the bot. Hermes changed /restart to wait for the current task to finish first — up to six hours — and during that wait the bot stays online, shows as healthy, and refuses every message. Restored to restarting straight away, as it did before.
  • Long replies and large output no longer cut the Chat tab. Hermes raised its WebSocket message limit to 384 MB while this proxy still stopped at 1 MB, so anything bigger silently dropped the connection mid-message with no error anywhere. Both ends now match.
  • Unexpected restart during very heavy tasks. Hermes added a watchdog that restarts the gateway if it stops responding for about two minutes. Kept on — this template already restarts the gateway cleanly — but a genuinely heavy task can now end in a restart rather than a reply.
  • Build pinned against upstream's new checks. Hermes now fails the build outright on the wrong Node.js version and blocks non-editable installs; both are pinned and documented so a future change can't quietly break the image.
Improvements
  • The "this won't survive a redeploy" notice now also covers the Tools tab. Installing a toolset from the dashboard wipes on the next deploy just like a memory provider, but used to warn you about neither — only the provider button did. Both now warn, and re-installing still restores everything, since your settings and keys live on the volume.

July 27, 2026
Git branch release/v2026.7.20/1 Hermes compatible version v2026.7.20
Hermes update
  • Updated Hermes Agent to v2026.7.20 (from v2026.7.1) — adds the new Hermes Console, session export, and three new providers: Fireworks AI, DeepInfra and Upstage Solar.
Changes to support upstream updates
  • Hermes Console. Hermes added a new console connection; this template only forwards connections it explicitly knows about, so the button failed. Added it to that list.
  • Restart throttling. Hermes added its own restart brake that paused the gateway before starting it — on top of the one this template already has. Turned Hermes' off so only ours applies; saving settings repeatedly no longer takes the bot offline.
  • Backups. Hermes can now leave your chat history out of a backup while still reporting success. The template now checks the file itself: a restore is refused unless its automatic safety snapshot is complete, and downloads warn instead of quietly handing you a partial file.
  • Paired users. Hermes now re-copies old pairing data on every start, which brought revoked users back. The template merges the old and new locations into one after a restore, so a revoke stays revoked.
  • Long replies. Hermes stopped sending keep-alive pings on its internal connection; this template was still expecting them and cut Chat off mid-reply. Matched Hermes' behaviour.
  • MCP sign-in. Hermes builds its return address from the web address it sees, which is internal behind this template's proxy. The template now tells Hermes its real public URL.
  • Memory providers. Hermes added a button that installs software into the running container, with no check for immutable deployments. The template now warns first — anything installed this way is lost on the next deploy.
  • Conversation auto-reset. Hermes changed its default, which would have made newly created deployments behave differently from existing ones. The template now sets it explicitly so both match.
Bug fixes
  • Fixed the Users tab reading the wrong location after a restore — pairing requests could be invisible and approvals ignored until the next restart.
  • Gateway shutdown now waits longer, so several connected chat platforms can disconnect cleanly instead of being cut off.
